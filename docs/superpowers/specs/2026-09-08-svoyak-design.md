# Свояк — дизайн-документ

Дата: 2026-09-08
Статус: утверждён к реализации

## 1. Что это

Веб-игра по правилам «Своей игры» для домашней компании. Один человек —
ведущий за ноутбуком, остальные подключаются с телефонов по QR-коду.
Вся игровая логика и состояние живут на сервере; клиенты — тонкие
отображения, которые не знают ничего сверх положенного их роли.

Режим запуска: локальная сеть либо туннель (cloudflared/ngrok) для игры
на расстоянии. Продакшн-развёртывания не планируется.

## 2. Ключевые решения

### 2.1 Хранение — JSON-файлы на диске

Паки по природе документы (раунд → тема → вопрос), запросов сложнее
«список / по id» нет, нагрузка — одна компания. JSON даёт ноль нативных
зависимостей, экспорт пака = сам файл, состояние читается и чинится
руками, бэкап = копирование папки.

    data/packs/<packId>.json      паки
    data/rooms/<code>.json        автосохранение живой игры
    data/history/<gameId>.json    завершённые игры
    uploads/<packId>/<file>       медиа

Запись атомарная: во временный файл рядом, затем rename. Доступ к диску
изолирован в `server/src/storage/*Repo.ts` — замена на SQLite потребует
правок только там.

### 2.2 Игровой движок — чистый редьюсер

    reduce(state: RoomState, action: GameAction) => { state: RoomState; effects: Effect[] }

Без I/O, без сети, без таймеров внутри. Таймеры и рассылка — снаружи, в
`RoomRuntime`; истечение таймера приходит в редьюсер обычным действием
`TIMER_EXPIRED`. Следствия:

- движок тестируется без сокетов;
- undo = стек снимков состояния (structuredClone, глубина 50);
- автосохранение = сериализация состояния после каждого действия
  (debounce 200 мс).

`Effect` — описание побочного действия для рантайма
(`{ type: 'setTimer' } | { type: 'clearTimer' } | { type: 'sound' } | { type: 'persist' }`),
сам редьюсер их только возвращает.

### 2.3 Проекции вместо общего состояния

Клиент получает не `RoomState`, а проекцию своей роли:

- `projectForHost(state)` — всё, включая ответы и комментарии;
- `projectForPlayer(state, playerId)` — без правильных ответов, без
  комментариев ведущего, без чужих финальных ставок и ответов, без
  содержимого нераскрытых клеток;
- `projectForBoard(state)` — табло и счёт, без ответов.

Это требование безопасности, а не оптимизация: правильный ответ не
должен уходить игроку по сети до раскрытия. Проверяется тестом,
который сериализует проекцию игрока и ищет в строке текст ответа.

Синхронизация — полная проекция на каждое изменение. Табло ~50 клеток и
до 10 игроков дают килобайты; дельты здесь только источник багов.

### 2.4 Честная кнопка

1. Клиент раз в 2 с шлёт `clock:ping{t0}`, получает `clock:pong{t0, tServer}`.
   Хранит минимальный RTT из последних 10 замеров и вычисленный офсет
   часов (min-RTT фильтр отсекает случайные задержки).
2. Нажатие уходит как `buzz{clientTime}`. Сервер переводит метку в своё
   время через офсет клиента и **валидирует**: метка не может быть в
   будущем и не может быть старше `now - maxPlausibleRtt`. Выход за
   границы — метка зажимается до момента приёма пакета.
3. Получив первое нажатие, сервер **не объявляет победителя сразу**, а
   открывает окно сбора `buzzGraceMs` (150 мс), собирает все нажатия и
   выбирает минимальную скорректированную метку. Без окна игрок с плохим
   каналом проигрывает пакету, а не реакции.
4. Нажатие до открытия кнопки — фальстарт: игрок блокируется на
   `falseStartLockMs` (по умолчанию 2500) в пределах этого вопроса,
   ведущий видит уведомление.

## 3. Модель данных

### 3.1 Пак

    Pack { id, title, author?, createdAt, updatedAt, rounds: Round[], final: FinalRound }
    Round { id, title, themes: Theme[] }
    Theme { id, title, comment?, questions: Question[] }
    Question {
      id, price, type: 'normal' | 'cat' | 'auction',
      text, media?: Media, answer, altAnswers: string[],
      answerMedia?: Media, hostComment?,
      cat?: { theme: string; price: number | 'nominal'; canKeep: boolean }
      // canKeep по умолчанию false: классический кот отдаётся другому игроку
    }
    Media { kind: 'image' | 'audio' | 'video'; src: string; }
    FinalRound { themes: FinalTheme[] }   // тема + один вопрос

Финальный раунд хранится отдельно от `rounds`, потому что играет по
другим правилам (нет цен, темы убираются).

### 3.2 Настройки комнаты

    RoomSettings {
      readingTimeMs: 3000        // от открытия вопроса до кнопки
      buzzOpenMs: 8000           // сколько всего кнопка открыта на вопрос
      buzzGraceMs: 150           // окно сбора нажатий
      falseStartLockMs: 2500
      answerTimeMs: 10000        // на устный ответ после нажатия
      soloAnswerTimeMs: 20000    // кот и аукцион — ответ без кнопки
      finalBetTimeMs: 60000 / finalAnswerTimeMs: 60000
      penaltyOnWrong: boolean    // штраф за неверный ответ
      allowNegative: boolean     // разрешать уход в минус
      finalRequiresPositive: boolean  // отсев нулей и минусов в финал
      auctionStep: 100           // минимальный шаг повышения ставки
    }

`buzzOpenMs` — общий бюджет времени на кнопку по вопросу: после неверного
ответа кнопка открывается остальным на **остаток** этого бюджета.

### 3.3 Состояние комнаты

    RoomState {
      code, createdAt, settings, packMeta,
      players: Player[],           // id, name, score, connected, sessionToken
      hostId,
      phase: Phase,
      roundIndex, board: BoardCell[][],   // цена + played
      currentQuestion?, controlPlayerId?, // право хода
      buzz?: { openedAt, locked: string[], candidates, answeringPlayerId, remainingMs },
      auction?, cat?, final?,
      history: LogEntry[],
      undoStack: RoomState[]        // не сериализуется в проекции
    }

### 3.4 Фазы

    lobby → round_intro → picking → reading
          → buzzer_open → answering → answer_reveal → picking
          → round_end → (следующий раунд | final_theme_removal)

    спецвопросы вместо кнопки:
    reading → cat_transfer → cat_answer → answer_reveal
    reading → auction_bidding → auction_answer → answer_reveal

    финал:
    final_theme_removal → final_bets → final_answers → final_reveal → results

Судейство — не отдельная фаза: ведущий выносит вердикт, находясь в
`answering`, `cat_answer`, `auction_answer` или `final_reveal`.

Пауза — флаг поверх фазы, а не отдельная фаза: замораживает таймеры.

## 4. Правила

- Право хода у игрока → он выбирает тему и цену. Ведущий видит, чей ход,
  и может переопределить выбор вручную.
- Верно: +цена, право хода переходит к ответившему.
- Неверно: −цена (если `penaltyOnWrong`), кнопка снова открывается для
  остальных на **оставшееся** время, ответивший в этом вопросе больше не
  участвует.
- Никто не ответил → ведущий раскрывает ответ, право хода остаётся у
  прежнего игрока.
- **Кот в мешке**: открывший передаёт вопрос выбранному игроку; цена
  может быть нестандартной; отвечает только получивший, без кнопки; при
  неверном ответе право хода остаётся у передавшего.
- **Аукцион**: торги начинаются с номинала, ходят по кругу от открывшего;
  ставка ≥ текущей + шаг (шаг 100, настраиваемый), максимум — свой счёт, «ва-банк» = весь счёт;
  пас; играет победитель один, без кнопки.
- **Финал**: игроки по очереди (от меньшего счёта) убирают темы, пока не
  останется одна; каждый втайне ставит от 1 до своего счёта и пишет
  ответ; ведущий вскрывает по очереди и судит. При
  `finalRequiresPositive` игроки с ≤0 в финал не проходят.
- Ведущий в любой момент: править счёт, кикнуть, пауза, «дать ещё время»,
  «снять вопрос», undo последнего действия.

## 5. Транспорт

Socket.IO, все события типизированы в `shared/src/events.ts`, `any`
запрещён. Три namespace не нужны — роль определяется при `join`.

Клиент → сервер (основное): `room:create`, `room:join`, `room:rejoin`,
`clock:ping`, `host:pickQuestion`, `host:judge`, `host:adjustScore`,
`host:undo`, `host:pause`, `player:buzz`, `player:bid`, `player:catPick`,
`player:finalRemoveTheme`, `player:finalBet`, `player:finalAnswer`.

Сервер → клиент: `state:sync` (проекция роли), `clock:pong`,
`sound:play`, `error`.

Реконнект: при `room:join` игрок получает `sessionToken` (uuid), клиент
кладёт его в localStorage; `room:rejoin{code, token}` возвращает к тому
же `Player` со счётом. Фолбэк — совпадение имени, если токен потерян.

## 6. Клиент

React + Vite + Tailwind + react-router. Состояние приходит с сервера,
поэтому тяжёлый стейт-менеджер не нужен: хук `useRoomState()` поверх
сокета и React context.

Маршруты: `/` (лендинг с выбором роли), `/host`, `/join`, `/play`,
`/board`, `/editor`.

Стиль: русский интерфейс, тёмная ТВ-эстетика — глубокий сине-фиолетовый
фон, золотые акценты, крупная типографика, анимация открытия клетки.

Мобильный экран игрока: кнопка во весь вьюпорт, `100dvh`, без скролла,
`touch-action: manipulation` и `user-scalable=no` против случайного зума,
крупные тапабельные зоны, тактильный отклик через `navigator.vibrate`.

Звуки синтезируются через WebAudio (короткие тоны на осцилляторах):
открытие кнопки, нажатие, верно, неверно, истечение времени. Бинарных
ассетов нет — ноль загрузки и вопросов с лицензиями. Переключатель в
localStorage.

## 7. Редактор паков

Работает без запущенной игры, поверх REST (`/api/packs`), не сокетов.

- CRUD пака / раунда / темы / вопроса, дублирование, drag-and-drop
  сортировка (`@dnd-kit`).
- Медиа: загрузка через multer в `uploads/<packId>/`, лимит 50 МБ.
- Быстрый режим — вставка темы текстом:

      Тема: Название
      100 | вопрос | ответ
      200 | вопрос | ответ

- Экспорт/импорт JSON.
- Валидация с предупреждениями: вопрос без ответа, неполная тема,
  дубли цен, битые ссылки на медиа.

## 8. Импорт .siq

`.siq` — ZIP с `content.xml` (SIGame). Формат менял версии: тип вопроса в
старых паках задаётся `<type name="cat"|"auction"|"sponsored">`, в новых —
иначе; имена медиафайлов URL-энкоденные, лежат в `Images/`, `Audio/`,
`Video/`.

Реализация: multer → распаковка (`yauzl`) → `fast-xml-parser` → маппинг в
нашу модель → извлечение медиа в `uploads/<packId>/`. Неизвестные
конструкции не роняют импорт: собирается **отчёт импорта** (что
смапилось, что пропущено, какие вопросы требуют ручной правки), который
показывается в UI. Молчаливая потеря вопросов недопустима.

## 9. Тестирование

Vitest, только серверный движок. Обязательные тесты:

1. подсчёт очков: верно / неверно со штрафом и без / запрет минуса;
2. окно кнопки: побеждает минимальная скорректированная метка, а не
   порядок пакетов;
3. фальстарт блокирует игрока и не блокирует остальных;
4. валидация метки времени клиента (метка из будущего зажимается);
5. переход права хода при верном, неверном и пустом ответе;
6. аукцион: минимум, ва-банк, пас, определение победителя;
7. кот в мешке: передача, нестандартная цена, отсутствие кнопки;
8. финал: отсев ≤0, границы ставки, вскрытие и судейство;
9. undo восстанавливает предыдущее состояние;
10. **проекция игрока не содержит текста правильного ответа**.

## 10. Запуск

`npm run dev` (npm workspaces + concurrently) поднимает сервер :3001 и
Vite :5173, который проксирует `/api`, `/uploads`, `/socket.io`. При
старте в консоль печатаются LAN-IP, ссылка `http://<ip>:5173/join?code=…`
и ASCII-QR.

`shared` подключается исходниками через tsconfig `paths` (сервер под
tsx) и `resolve.alias` (Vite) — промежуточной сборки нет, правки типов
видны сразу.

README: установка, запуск, создание пака, ход игры, инструкция по
туннелю (cloudflared/ngrok) для игры на расстоянии.
