# Настройка игры ведущим: несколько паков, раунды, таймер чтения

Дата: 2026-09-09

## Задача

Сейчас комната создаётся одним кликом по паку: игра = пак целиком, настройки
не видны ведущему, кнопку на каждом вопросе он открывает руками. Нужно дать
ведущему собрать игру: какие паки идут в дело, сколько раундов и тем, нужен ли
автоматический таймер перед открытием кнопки.

Отдельно: страница редактирования пака едет по горизонтали — ширина карточки
зависит от длины самого длинного вопроса.

## Решение

### Рецепт вместо пака

```ts
interface ThemeRef { packId: string; themeId: string }
interface GameRecipe { rounds: ThemeRef[][]; final: ThemeRef[] }
```

Мастер собирает рецепт, сервер по нему строит обычный `Pack` и кладёт в комнату
как сегодня. Движок, доска, undo, персистенс и проекции не меняются.

Отвергнутые варианты:

- Хранить рецепт в комнате и резолвить темы на лету — движку нужен доступ к
  репозиторию паков, а сохранённая комната ломается при правке или удалении пака.
- Собирать микс как настоящий пак в редакторе — отдельная большая фича и мусор
  в списке паков после каждой игры.

### Сборка (`server/src/packs/compose.ts`)

`buildPackFromRecipe(recipe)`:

- **нормализует цены по сетке раунда**: цена i-го вопроса равна
  `(i + 1) * 100 * номер_раунда`. Без этого тема из первого раунда одного пака
  (100–500) и тема из второго раунда другого (200–1000) окажутся в одном раунде
  с разной сеткой.
- **перевыдаёт идентификаторы** с префиксом раунда и позиции: одна и та же тема,
  взятая дважды, не должна ломать доску.

`draftRecipe(...)` набирает случайный рецепт по seed: детерминированный, чтобы
«пересобрать» давало воспроизводимый результат и чтобы это можно было проверить
тестом.

### Контракт

- `room:create` принимает `{ recipe, settings }` либо прежнее `{ packId, settings }`.
- Новое `room:setup { recipe?, settings? }` — только ведущему и только в фазе `lobby`.

### Таймер чтения

- `RoomSettings`: `readingMs` (умолчание 5000) и `autoOpenBuzzer` (умолчание `true`).
- Новый `TimerKind: 'reading'`.
- На `PICK_QUESTION`, когда фаза становится `reading`, движок ставит таймер с
  `onExpire: OPEN_BUZZER`. Спецвопросы идут мимо: у кота и аукциона своя фаза,
  кнопки там нет.
- Ведущий по-прежнему может открыть кнопку раньше; `setTimer` на кнопку заменяет
  таймер чтения. При `autoOpenBuzzer: false` поведение ровно сегодняшнее.

### Экран мастера

`/host` до создания комнаты: паки (чекбоксы) → состав (раундов, тем в раунде,
тем в финале, превью с заменой темы) → настройки (пресеты плюс раскрывающийся
блок со всеми числами). В лобби те же блоки, редактируемые до старта.

### Редактор: ширина

Причина: `min-width: auto` у грид- и флекс-потомков плюс `truncate`
(`white-space: nowrap`) в свёрнутой строке вопроса. Минимальная ширина карточки
становится равной длине самого длинного вопроса и перебивает `max-w-5xl`.
Замер до фикса: `scrollWidth` 1562 при `clientWidth` 1512.

Фикс: `min-width: 0` контейнерам внутри редактора, `overflow-x: clip` на корне
как страховка.

## Вне объёма

Drag&drop-конструктор тем, сохранение микса как пака, выбор отдельных вопросов
внутри темы.
